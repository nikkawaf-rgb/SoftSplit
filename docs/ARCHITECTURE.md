# Архитектура SoftSplit

Документ описывает, как устроен проект внутри, какие технические решения приняты и почему,
а также где точки расширения под будущую графическую оболочку.

---

## 1. Общая картина

```
┌──────────────────────────────────────────────────────────────────────┐
│  mirror-on.cmd                                                       │
│    └─> powershell -File MirrorWindow.ps1                             │
│          ├─ Add-Type: DpiFix (SetProcessDPIAware)                    │
│          ├─ Add-Type: Ccd   (QueryDisplayConfig + GetDeviceInfo)     │
│          ├─ построение карты «GDI-имя ↔ имя монитора»                │
│          ├─ выбор source/target по подстрокам имени                  │
│          ├─ WinForms Form (borderless, TopMost, bounds = TV)         │
│          ├─ WinForms Timer (1000/Fps мс)                              │
│          │     └─ Graphics.CopyFromScreen(LG) -> Bitmap -> PictureBox│
│          └─ PID в %TEMP%\SoftSplitMirror.pid                         │
└──────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────┐
│  mirror-off.cmd                                                      │
│    └─> читает PID-файл, Stop-Process -Id, удаляет PID-файл           │
└──────────────────────────────────────────────────────────────────────┘
```

Оба скрипта — самодостаточные: весь C#-код компилируется на лету через `Add-Type`,
внешних зависимостей и установки нет.

## 2. Компоненты

### 2.1 `MirrorWindow.ps1` — ядро

| Блок | Ответственность |
|---|---|
| `DpiFix.SetProcessDPIAware()` | Приводит координаты и размеры окон к физическим пикселям |
| Класс `Ccd` | Чтение активной топологии через CCD API; возвращает пары `\\.\DISPLAYn|FriendlyName` |
| `Find-Screen` | Выбор экрана по подстроке человекочитаемого имени |
| `Form` + `PictureBox` | Полноэкранная поверхность на телевизоре |
| `Timer` | Регулярный захват кадра источника |
| PID-файл | Одноэкземплярность и корректное завершение извне |

### 2.2 `MirrorDisplay.ps1` — работа с топологией

Умеет три вещи:

- `-Action status` — распечатать активные пути: имя монитора, `source id`, режим источника
  и режим приёмника (через `DISPLAYCONFIG_MODE_INFO`).
- `-Action off` — применить `SDC_TOPOLOGY_EXTEND | SDC_APPLY` (аварийное восстановление).
- `-Action on` — попытка штатного клонирования через подмену `sourceInfo`.

Последнее **намеренно оставлено как исследовательский код**: на телевизоре без режима
2560×1440 оно возвращает `ERROR_INVALID_PARAMETER (87)`. См.
[HDMI-INVESTIGATION.md](HDMI-INVESTIGATION.md), раздел «Эксперименты с CCD».

### 2.3 `.cmd`-обёртки

Тонкие: запускают PowerShell скрыто (`mirror-on`) или читают PID и останавливают процесс
(`mirror-off`, `fix-layout`). Логика в них не живёт — так её проще заменить GUI.

## 3. Почему приняты именно такие решения

### 3.1 Почему не настоящее клонирование (CCD/SetDisplayConfig)

Клонирование в Windows означает: несколько путей (`DISPLAYCONFIG_PATH_INFO`) ссылаются на
**один и тот же source**. Проверка показала:

- Windows умеет это делать (`SDC_TOPOLOGY_CLONE` отработал), но при трёх дисплеях она
  сдублировала монитор 1080p и основной 1440p, а телевизор **выбросила из топологии**;
- ручная подмена source у телевизора даёт `87 (ERROR_INVALID_PARAMETER)` во всех
  вариантах: с целевым режимом 4K, со синтезированным 1440p60, с
  `SDC_VIRTUAL_MODE_AWARE`, с `SDC_ALLOW_PATH_ORDER_CHANGES`, с полным набором
  `QDC_ALL_PATHS`;
- причина: телевизор не заявляет 2560×1440 ни в EDID, ни в списке режимов драйвера
  (проверено — 184 режима, 1440p отсутствует).

Вывод: клон пары 1440p → 4K-ТВ невозможен на уровне ОС. Остаётся либо даунгрейд всех
до 1080p, либо вывод окном.

### 3.2 Почему окно, а не виртуальный дисплей / драйвер

- Виртуальные адаптеры (IDD) требуют установки драйвера и подписи — тяжело и хрупко.
- Окно работает на любых драйверах, не требует прав администратора и не меняет топологию:
  если его закрыть, система остаётся ровно такой, какой была.

### 3.3 Почему CCD для имён, а не `EnumDisplayDevices`

`EnumDisplayDevices` возвращает служебные строки адаптера и монитора, но не гарантирует
человекочитаемого имени в нужном формате. `Screen.AllScreens` даёт только `\\.\DISPLAYn`.
CCD связывает source (у которого есть GDI-имя, `DISPLAYCONFIG_DEVICE_INFO_GET_SOURCE_NAME`)
и target (у которого есть EDID-имя, `DISPLAYCONFIG_DEVICE_INFO_GET_TARGET_NAME`) — это
единственный надёжный способ сопоставить «Philips FTV» и `\\.\DISPLAY3`.

### 3.4 Почему DPI-awareness обязателен

Телевизор 3840×2160 с масштабом 300 % в не-DPI-aware процессе выглядит как 1280×720 со
смещением 4480,0. Окно тогда создаётся «в четверть панели» и физически занимает только
верхний левый угол 4K-матрицы. Вызов `SetProcessDPIAware()` до создания окон решает это.

### 3.5 Почему `CopyFromScreen`, а не Desktop Duplication / Windows Graphics Capture

- `CopyFromScreen` (GDI BitBlt) — одна строка кода, без COM/WinRT interop, работает
  в PowerShell 5.1 без плясок с `IInitializeWithWindow`.
- Плата: 30 fps и отсутствие курсора. Для просмотра видео и «показать картинку на большом
  экране» этого достаточно; при необходимости частоту можно поднять до 60.
- Более производительный путь (WGC/DXGI) — кандидат на версию 0.3+, когда появится GUI
  и нативная сборка (см. [ROADMAP.md](../ROADMAP.md)).

## 4. Жизненный цикл и надёжность

- **Одноэкземплярность**: перед созданием окна читается `%TEMP%\SoftSplitMirror.pid`;
  если процесс жив — выход с сообщением `Already running`.
- **Завершение**: PID-файл удаляется в блоке `finally`, то есть и при `Esc`, и при
  `Stop-Process` из `mirror-off.cmd` (файл останется только при жёстком убийстве процесса —
  тогда его можно удалить вручную, приложение это переживёт).
- **Устойчивость таймера**: тело обработчика обёрнуто в `try/catch` — временная ошибка
  захвата кадра не роняет окно.
- **Отсутствие телевизора**: если target не найден (ТВ выключен), скрипт завершается
  с понятным сообщением и кодом 1, ничего не меняя в системе.

## 5. Точки расширения под GUI

Текущий код — один монолитный скрипт, что нормально для 0.1.0. Для оболочки логично
разделить (подробнее — [ROADMAP.md](../ROADMAP.md)):

1. **Ядро** (`SoftSplit.Core.psm1` или отдельная сборка):
   - `Get-DisplaysInfo` — список дисплеев (GDI-имя, имя, режим, позиция, primary);
   - `Start-Mirror -Source -Target -Fps` / `Stop-Mirror` / `Test-Mirror`;
   - конфиг в `%APPDATA%\SoftSplit\config.json`.
2. **UI** — WinForms/WPF поверх ядра: выбор источника и приёмника из выпадающих списков,
   слайдер FPS, тумблер «включено», горячая клавиша, иконка в трее.
3. **Автозапуск** — через `HKCU\...\Run` или Планировщик, переключатель в UI.

Ключевое требование при рефакторинге: сохранить работу «голых» `.cmd` как аварийного пути.

## 6. Известные ограничения архитектуры

| Ограничение | Причина | Возможное решение |
|---|---|---|
| Нет курсора на ТВ | GDI BitBlt не рисует курсор | Рисовать курсор вручную по `GetCursorPos`, либо перейти на WGC |
| Чёрный кадр на DRM-контенте | Защищённый вывод не копируется | Только аппаратный клон (сплиттер) |
| 30–60 fps | GDI-копирование | WGC/DXGI, либо аппаратный сплиттер |
| Задержка 30–60 мс | Захват + отрисовка | Аппаратный клон |
| Мигание ТВ в standby не лечится | Это уровень HPD/EDID | CEC-блокер, EDID-эмулятор |
| Зависимость от подстрок имён | Простота | Ручной выбор из списка в GUI |
