# Как устроен SoftSplit

Документ про внутреннее устройство: из каких частей состоит программа, какие технические
решения приняты и почему. Если нужны только ограничения и цифры — смотрите
[LIMITATIONS.md](LIMITATIONS.md).

---

## 1. Общая картина

```
SoftSplit.exe (WinForms)
├─ Ui
│   ├─ SettingsForm        — окно настроек: список дисплеев и их роли
│   ├─ TrayIcon            — иконка в трее и контекстное меню
│   └─ HotkeyHook          — глобальная горячая клавиша включения/выключения
├─ Core
│   ├─ DisplayCatalog      — какие дисплеи есть, как они называются, какие режимы умеют
│   ├─ TopologyService     — смена разрешения дисплея, аварийный возврат к «Расширить»
│   ├─ MirrorEngine        — что дублировать куда, жизненный цикл окон и кадров
│   ├─ DxgiSession         — быстрый путь: Desktop Duplication + swap chain
│   ├─ ScreenCapture       — резервный путь: BitBlt + StretchBlt
│   ├─ ConfigStore         — чтение и запись %APPDATA%\SoftSplit\config.json
│   └─ Autostart           — запись в HKCU\...\Run
└─ Program                 — один экземпляр, запуск из трея, разбор аргументов
```

Программа состоит из двух слоёв: **UI** ничего не знает про Win32, а **Core** ничего не
знает про окна настроек. Это позволяет позже заменить движок захвата, не переделывая
интерфейс.

## 2. Каталог дисплеев: почему CCD API

Задача кажется простой: получить список мониторов с человекочитаемыми именами.
На практике в Windows это нетривиально:

| Способ | Что даёт | Почему не подходит |
|---|---|---|
| `Screen.AllScreens` | `\\.\DISPLAY1`, координаты, размер | Нет имён мониторов, нельзя отличить один 4K-телевизор от другого |
| `EnumDisplayDevices` | Служебные строки адаптера и устройства | Не гарантирует человекочитаемого имени в нужном формате |
| **CCD API** (`QueryDisplayConfig` + `DisplayConfigGetDeviceInfo`) | Пары «GDI-имя ↔ имя монитора из EDID» | — |

Поэтому `DisplayCatalog` использует CCD: `DISPLAYCONFIG_DEVICE_INFO_GET_SOURCE_NAME` даёт
GDI-имя (`\\.\DISPLAY2`), `..._GET_TARGET_NAME` — имя из EDID («ACME 27»). Список
поддерживаемых режимов берётся через `EnumDisplaySettings` по GDI-имени.

Мониторы определяются **по идентификатору устройства**, а не по подстроке имени: у
пользователя может быть два одинаковых монитора, и имя у них будет одинаковое.

## 3. Роли дисплеев

Каждому дисплею назначается одна из ролей:

- **Расширить** — дисплей остаётся частью рабочего стола, программа его не трогает,
  кроме разрешения, если пользователь его явно выбрал;
- **Дублировать** — дисплей показывает содержимое другого дисплея.

Схема хранится как список: `id дисплея → роль + (для дубля) id источника`.

Дублирование реализуется **окном**: на целевом дисплее создаётся окно без рамки, без
заголовка, поверх остальных окон, размером ровно в границы дисплея. В окно выводится кадр,
снятый с дисплея-источника.

## 4. Почему окно, а не «настоящий» клон

Клонирование в терминах Windows означает: несколько **target**-устройств ссылаются на один
и тот же **source**. Ограничение встроено в модель: у клона один источник, а значит один
режим источника. Чтобы картинка совпала, каждый target обязан поддержать этот режим —
либо сам, либо через масштабирование на GPU, которое Windows применяет не всегда.

Отсюда два практических следствия:

1. Если у дисплеев **есть общий режим** — клон работает, и это лучший вариант: нулевая
   задержка, нулевая нагрузка, работает защищённый контент.
2. Если общего режима нет (например, источник 2560×1440, а приёмник умеет только
   1920×1080 и 3840×2160) — `SetDisplayConfig` либо отказывается, либо переводит **все**
   дисплеи в общий режим, обычно самый низкий.

Документировать это как «Windows сломана» неправильно: это следствие того, что разрешение
дисплея определяется его EDID, а не желанием пользователя. Программа обходит ограничение
тем, что **не меняет топологию**: приёмник остаётся обычным расширенным дисплеем со своим
нативным режимом, а картинка в него просто рисуется. Закрытие программы или выключение
дублирования возвращает всё как было — в системе ничего не «залипает».

Плата за это — та самая задержка в один кадр, о которой честно написано в
[LIMITATIONS.md](LIMITATIONS.md), и невозможность показать защищённый контент.

## 5. DPI: почему это критично

Windows позволяет приложениям объявлять себя DPI-aware на нескольких уровнях. Разница
принципиальна при масштабировании 150–300 %:

| Уровень | Что видит приложение на дисплее 3840×2160 при масштабе 300 % |
|---|---|
| DPI-unaware | 1280×720, окно рисуется в этом разрешении и растягивается системой втрое |
| System aware | 1280×720 (система всё равно масштабирует битмап) |
| **Per-monitor v2** | **3840×2160 — честные физические пиксели** |

SoftSplit объявляет **Per-monitor v2** в манифесте. Иначе картинка на 4K-приёмнике
проходила бы двойное масштабирование: 1440p → 720p → 4K, то есть выглядела бы мылом.
Проверить, что приложение получило именно физические пиксели, можно в окне диагностики.

## 6. Захват кадра

Кадр снимается один раз за тик и **раздаётся всем приёмникам одного источника** — не
важно, дублируется дисплей на один экран или на три.

Есть два пути, и программа выбирает их автоматически:

### 6.1 Быстрый путь: Desktop Duplication и swap chain

1. `IDXGIOutput1.DuplicateOutput` подписывается на обновления конкретного дисплея.
2. `AcquireNextFrame` отдаёт текстуру кадра **в видеопамяти** — она копируется в собственную
   текстуру и сразу освобождается.
3. Для каждого окна-приёмника создан `SwapChain1` с flip-моделью на `HWND`. Кадр рисуется
   полноэкранным треугольником с шейдером, который сэмплирует текстуру с линейной
   фильтрацией; масштабирование делает видеокарта.
4. `Present` вызывается только когда пришёл новый кадр.

Процессор здесь не участвует в переносе пикселей вообще: он только забирает и отдаёт
несколько COM-вызовов. Отсюда 2–3 % одного ядра вместо десятков процентов.

### 6.2 Резервный путь: GDI

Если Desktop Duplication недоступен (сеанс RDP, часть виртуальных машин, старый драйвер),
программа работает так:

- съём `BitBlt` из экранного DC в DIB-секцию в памяти;
- курсор рисуется отдельно (`GetCursorInfo` + `DrawIconEx`), потому что `BitBlt` его не
  захватывает;
- вывод — `StretchBlt` в окно.

Этот путь медленнее на порядок, зато работает всегда и умеет рисовать курсор.

### 6.3 Общее

- Частота: таймер с интервалом `1000 / fps`, по умолчанию 30 fps — компромисс между
  плавностью и нагрузкой.
- Ошибки съёма (например, режим меняется прямо сейчас) гасятся и не роняют окно.
- Конкретные цифры нагрузки — в [LIMITATIONS.md](LIMITATIONS.md).

## 7. Масштабирование

Приёмник рендерится в своём режиме. Если пропорции источника и приёмника не совпадают,
пользователь выбирает:

| Режим | Поведение |
|---|---|
| **Вписать** | Сохранить пропорции, при необходимости добавить чёрные поля (letterbox) |
| **Заполнить** | Сохранить пропорции, обрезать лишнее по краям |
| **Растянуть** | Заполнить весь экран без сохранения пропорций |

Интерполяция — бикубическая: при выводе 1440p на 4K это заметно лучше, чем bilinear.

## 8. Настройки и автозапуск

Конфиг лежит в `%APPDATA%\SoftSplit\config.json`:

```json
{
  "Version": 1,
  "Fps": 30,
  "ShowCursor": true,
  "Autostart": false,
  "StartMirroringOnLaunch": true,
  "UseGpu": true,
  "Displays": [
    { "DevicePath": "DISPLAY#...UID4355#...", "Role": "extend", "SourcePath": null, "Scale": "fit" },
    { "DevicePath": "DISPLAY#...UID4352#...", "Role": "duplicate", "SourcePath": "DISPLAY#...UID4355#...", "Scale": "fit" }
  ]
}
```

Автозапуск — запись в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. Он выбран
вместо Планировщика заданий, потому что не требует прав администратора и не создаёт
отдельного узла, который пользователю потом трудно найти и удалить.

Один экземпляр программы обеспечивается именованным мьютексом: повторный запуск не
создаёт второе приложение, а открывает окно уже работающего.

## 9. Надёжность

- Любые изменения режимов дисплея применяются через `TopologyService` с проверкой
  результата; при ошибке программа возвращается к предыдущей раскладке.
- Кнопка **«Вернуть обычную раскладку»** применяет `SDC_TOPOLOGY_EXTEND` — аварийный
  выход из любой ситуации с режимами.
- Окна-приёмники не появляются в панели задач и в Alt+Tab и не забирают фокус.
- Если целевой дисплей отключили, его окно закрывается, а при возврате дисплея —
  создаётся заново (слежение за `WM_DISPLAYCHANGE`).

---

## 10. Точки расширения

- **Пути захвата** разделены: `DxgiSession` и `ScreenCapture` с одинаковым контрактом
  «снять кадр / вывести кадр». Третий путь (например, Windows Graphics Capture) добавляется
  рядом, без правок в UI.
- **Движок дублирования** — тоже интерфейс: рядом с оконным вариантом может появиться
  нативный клон через `SetDisplayConfig` для пар, у которых есть общий режим.
- **Профили** (наборы ролей под разные задачи) ложатся на `ConfigStore` без изменения
  остальных слоёв.
