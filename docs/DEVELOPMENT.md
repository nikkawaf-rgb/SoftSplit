# Разработка

Правила, сборка, отладка и процесс работы над проектом.

---

## 1. Требования к окружению

- Windows 10/11 x64 — целевая платформа.
- **.NET SDK 8.0 или новее** (проверено на 10.0) — для сборки.
- Доступ к NuGet: пакеты ссылочных сборок .NET Framework и SharpDX (Direct3D 11).
  Visual Studio не обязательна.

```powershell
dotnet --version      # должно быть 8.0 или выше
```

Приложение собирается под **.NET Framework 4.8**: он есть в любой поддерживаемой Windows,
поэтому пользователю не нужно ничего доустанавливать, а размер сборки — сотни килобайт плюс
несколько небольших библиотек SharpDX.

## 2. Структура

```
SoftSplit/
├─ src/SoftSplit/
│   ├─ SoftSplit.csproj
│   ├─ Program.cs              # точка входа, аргументы, один экземпляр
│   ├─ app.manifest            # Per-monitor v2 DPI
│   ├─ app.config              # WinForms DPI-настройки
│   ├─ SoftSplitApp.cs         # связка «настройки + дисплеи + движок»
│   ├─ TrayApplicationContext.cs  # жизненный цикл трея
│   ├─ assets/softsplit.ico
│   ├─ Core/
│   │   ├─ DisplayCatalog.cs   # CCD-каталог дисплеев и режимов
│   │   ├─ TopologyService.cs  # смена режимов, аварийное «Расширить»
│   │   ├─ MirrorEngine.cs     # окна-приёмники и цикл кадров
│   │   ├─ DxgiSession.cs      # быстрый путь: DD + swap chain + шейдер
│   │   ├─ ScreenCapture.cs    # резервный путь: BitBlt/StretchBlt
│   │   ├─ MirrorWindow.cs     # окно-приёмник
│   │   ├─ Placement.cs        # вписать / заполнить / растянуть
│   │   ├─ ConfigStore.cs      # config.json
│   │   ├─ Autostart.cs        # HKCU\...\Run
│   │   └─ Native.cs           # P/Invoke
│   └─ Ui/
│       ├─ SettingsForm.cs
│       └─ TrayIcon.cs
├─ tools/make-icon.ps1         # генератор иконки
├─ docs/
├─ README.md, CHANGELOG.md, ROADMAP.md, CONTRIBUTING.md, LICENSE
```

UI и Core разделены: Core не знает про окно настроек и трей.

## 3. Сборка и запуск

```powershell
# отладочная сборка
dotnet build .\src\SoftSplit\SoftSplit.csproj -c Debug

# запуск
.\src\SoftSplit\bin\Debug\net48\SoftSplit.exe

# релизная сборка
dotnet build .\src\SoftSplit\SoftSplit.csproj -c Release
```

Portable-архив для релиза:

```powershell
dotnet publish .\src\SoftSplit\SoftSplit.csproj -c Release -o .\dist
Compress-Archive .\dist\* .\SoftSplit-win64.zip -Force
```

В `dist` попадают `SoftSplit.exe`, `SoftSplit.exe.config`, несколько сборок SharpDX и
файлы локализации SharpDX. Всё это распаковывается в одну папку и запускается.

## 4. Кодировка исходников

- Все `.cs`, `.md`, `.json` — **UTF-8**.
- Строки интерфейса на русском живут прямо в коде; файлы компилируются как UTF-8, поэтому
  BOM не требуется. Если правите файл старым редактором, который пишет CP1251, русский текст
  превратится в мусор — проверяйте кодировку перед коммитом.
- Переносы строк — LF (`.gitattributes` это фиксирует).

## 5. Отладочные режимы

```powershell
.\SoftSplit.exe --verbose     # подробный вывод в консоль и журнал
.\SoftSplit.exe --diagnose    # отчёт о дисплеях и топологии
.\SoftSplit.exe --probe-dx    # есть ли Direct3D 11 и Desktop Duplication
.\SoftSplit.exe --gdi         # принудительно резервный путь (нужен для отладки курсора)
.\SoftSplit.exe --minimized   # только трей, без окна настроек
```

Полезно помнить:

- окна-приёмники живут в том же процессе, что и трей; их ошибки перехватываются и
  записываются в `%APPDATA%\SoftSplit\log.txt`, но не роняют приложение;
- в быстром режиме окна ничего не рисуют сами: кадр выводит swap chain, поэтому `OnPaint`
  в `MirrorWindow` намеренно пустой;
- перезапуск после правки кода — обычный `dotnet build` + запуск;
- `--probe-dx` и `--diagnose` — первое, что стоит приложить к сообщению об ошибке.

## 6. Чек-лист перед коммитом

1. `dotnet build -c Release` проходит без предупреждений, значимых для поведения.
2. `--diagnose` показывает все подключённые дисплеи с правильными разрешениями.
3. Дублирование включается, окно занимает **весь** дисплей, а не его часть.
4. Повторный запуск не создаёт второй экземпляр.
5. Выключение дублирования закрывает окна и не оставляет следов в раскладке.
6. Настройки переживают перезапуск.
7. В репозитории нет личных данных: имён устройств, скриншотов рабочего стола с личной
   информацией, путей вида `C:\Users\...`.

## 7. Git-процесс

```powershell
git status
git add -A
git commit -m "feat: короткое описание"
git push
```

Сообщения — упрощённый Conventional Commits:

| Префикс | Когда |
|---|---|
| `feat:` | новая функциональность |
| `fix:` | исправление |
| `docs:` | только документация |
| `refactor:` | перестройка без изменения поведения |
| `chore:` | служебное (сборка, зависимости) |

Ветки: `main` — рабочая; под фичи — `feature/...`. Теги — по версиям: `v0.2.0`.

## 8. Как добавить новый движок захвата

1. Реализуйте `IFrameSource`: метод «снять кадр в буфер» плюс размеры и признак «доступен».
2. Подключите его в `MirrorEngine` вместо текущего съёма через `BitBlt`.
3. Проверьте на конфигурации с масштабом 150–300 %: координаты и размеры должны быть
   физическими пикселями.

Требование, которое нельзя терять: **программа не должна требовать прав администратора и
не должна менять топологию дисплеев ради дублирования** — только ради явно выбранного
пользователем разрешения.

## 9. Стиль кода

- Пространства имён — `SoftSplit.Core`, `SoftSplit.Ui`.
- Публичные методы — глагол + существительное (`RefreshDisplays`, `ApplyRoles`).
- Комментарии — по-английски, только там, где неочевидно; пользовательские тексты — на
  русском.
- Никаких внешних зависимостей без необходимости: каждая библиотека — это ещё один способ
  сломать запуск у пользователя.
