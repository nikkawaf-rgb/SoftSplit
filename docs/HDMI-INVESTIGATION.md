# Расследование: почему дублирование 2К на телевизор невозможно и откуда мигание

Документ фиксирует результаты диагностики реальной конфигурации (2026-11-16/17),
чтобы не повторять её заново и понимать границы применимости проекта.

---

## 1. Исходная картина

| Компонент | Детали |
|---|---|
| ПК | Windows 11, build 26300, NVIDIA GeForce RTX 3060 Ti (драйвер 32.0.16.1088) |
| Основной монитор | LG ULTRAGEAR, 2560×1440 @ 165 Гц (`\\.\DISPLAY1`, target 4355) |
| Вспомогательный | AOC 2769M, 1920×1080 @ 60 Гц (`\\.\DISPLAY2`, target 4353), максимум — Full HD |
| Телевизор | Philips 65" 4K, `PHL04C3`, `\\.\DISPLAY3`, target 4352 |
| Кабель | оптический (AOC) HDMI, **15 м**, проложен в стене, замена невозможна |
| Доп. ПО | Meta Horizon Link (Quest 2), Sunshine + Moonlight, SideQuest |

Симптом: при **выключенном** телевизоре экран периодически гаснет и заново подстраивается
под разрешение (хаотично: от секунд до минут). При включённом — всё нормально.

## 2. Как устроен HDMI и почему это происходит

- **HPD (Hot Plug Detect, пин 19)** — линия, которой приёмник сообщает источнику «я подключён».
  Пока она поднята, видеокарта держит дисплей активным.
- **EDID** — таблица поддерживаемых режимов, читается по линии **DDC** после поднятия HPD.
- **Link training** — согласование скорости/кодирования перед передачей картинки.

Что происходит при уходе телевизора в дежурный режим:

1. ТВ снимает HPD → видеокарта считает, что кабель выдернули → Windows удаляет дисплей и
   пересобирает раскладку. Первое «мигание».
2. В дежурке Philips не «мёртв»: он периодически подаёт питание на HDMI-приёмник — для
   CEC/EasyLink, сетевого standby, проверки обновлений. Каждый импульс — HPD снова поднят,
   Windows перечитывает EDID и применяет режим. Второе «мигание» и так далее.
3. Оптический кабель добавляет риск: питание приёмного конца идёт по +5 В источника,
   запас по линии меньше, чем у пассивного медного. Сбой чтения EDID → откат на безопасный
   режим пониже (то самое «приспосабливается к разрешению»).

Хаотичный ритм объясняется таймерами телевизора, а не Windows.

## 3. Что показала диагностика

### 3.1 Целостность системы — чисто

- `DISM /Online /Cleanup-Image /CheckHealth` → «Повреждение хранилища компонентов не
  обнаружено», exit code 0.
- `sfc /scannow` → нарушений целостности нет; в `CBS.log` нет записей `Cannot repair member file`.
- `chkdsk C: /scan` → проблем нет.
- Пять физических дисков: `Healthy`, `PredictFailure = False` для всех.
- Версия «почистил ПК и убил системные файлы» — **не подтвердилась**.

> Замечание: 179 «проблемных устройств» в отчёте — это `CM_PROB_PHANTOM`, «призраки»
> давно отключённых флешек и телефонов. Это норма Windows, а не неисправность.

### 3.2 Найден сломанный виртуальный дисплей

- Устройство `ROOT\DISPLAY\0000`, `Root\MetaVirtualScreenDriver`, драйвер 11.1.45.729,
  INF `oem109.inf`, производитель Meta Inc. — виртуальный экран из **Meta Horizon Link**.
- Служба устройства — `WUDFRd`, и она **27 раз за 7 дней** не смогла загрузить драйвер:
  `Event 219`, состояние `0xC0000365` (`STATUS_FAILED_DRIVER_ENTRY`).
- Сам по себе дефект реальный, но 27 отказов за неделю (3–4 в сутки) **не совпадают**
  с частотой мигания «раз в секунды/минуты». Вывод: это вторичный фактор, усиливающий
  перестройку конфигурации, но не её первопричина.

### 3.3 Настройки телевизора

Что было сделано и что помогло:

| Действие | Эффект |
|---|---|
| EasyLink (HDMI-CEC) → выкл. | Убирает главный источник опроса HDMI в дежурке |
| `HDMI Ultra HD`: `Optimal` → `Standard` | Снижает требования к полосе (4:2:0, 8 бит вместо 4:4:4/12 бит) — линк перестал срываться |
| ПК на порт HDMI 2 (не ARC) | ARC-порт опрашивается активнее, туда лучше ставить приставку |

После этих изменений мигание прекратилось на время наблюдения.

### 3.4 Эксперименты с CCD API (ключевой результат)

Все проверки — на живой машине, через `QueryDisplayConfig` / `SetDisplayConfig`.

**a) Активная топология (extend):**

```
LG ULTRAGEAR  source=0  2560x1440  target=2560x1440
2769M         source=1  1920x1080  target=1920x1080
Philips FTV   source=2  3840x2160  target=3840x2160
```

**b) `SDC_TOPOLOGY_CLONE` (дублировать всё) — «успех» с побочным эффектом:**

```
2769M         source=0  1920x1080  target=1920x1080
LG ULTRAGEAR  source=0  1920x1080  target=1920x1080
```

Телевизор **выпал из топологии**, а оба оставшихся дисплея сдублировались в 1080p
(общий режим — по самому слабому). То есть «просто продублировать» в этой конфигурации
означает потерять телевизор и разрешение.

**c) Ручное клонирование (подмена `sourceInfo` телевизора на source основного монитора):**

Пробовали все разумные варианты и получали `87 (ERROR_INVALID_PARAMETER)`:

| Вариант | Флаги | Результат |
|---|---|---|
| Источник 1440p, цель 4K | `USE_SUPPLIED \| ALLOW_CHANGES \| APPLY` | 87 |
| Источник 1440p, цель 1440p60 (синтезированный режим) | то же | 87 |
| То же + `SDC_VIRTUAL_MODE_AWARE` | + `0x8000` | 87 |
| То же + `SDC_ALLOW_PATH_ORDER_CHANGES` | + `0x2000` | 87 |
| Полный набор путей `QDC_ALL_PATHS` + `SDC_VALIDATE` | — | 87 |

**d) Почему так — ответ в списке режимов телевизора.**

`EnumDisplaySettings` для `\\.\DISPLAY3` вернул **184 режима**: 3840×2160, 1920×1080,
1680×1050, 1600×1200, …, 640×480 — с шагом частот 60/59/50/30/29/25/24/23 Гц.
**Режима 2560×1440 в списке нет.** Клонирование требует единого режима для источника и
приёмника, а общего 1440p у LG и ТВ не существует. Отсюда и `87`.

## 4. Выводы

1. Нативное дублирование «2К-монитор → этот телевизор» **невозможно** — ни через
   панель управления, ни через CCD API. Ограничение в EDID/драйвере телевизора.
2. Любой «клон» в этой системе деградирует до 1920×1080 и, как побочный эффект,
   может выбросить телевизор из топологии.
3. Единственный способ показать 1440p на 4K-панели — **вывод окном с масштабированием**.
   Это и реализует SoftSplit.
4. Мигание при выключенном ТВ — следствие поведения HPD в дежурном режиме и (вероятно)
   запаса по линии оптического кабеля. Лечится настройками ТВ, а аппаратно —
   CEC-блокером, EDID-эмулятором или сплиттером.

## 5. Рекомендации по железу (без вскрытия стены)

Все устройства ставятся в разрыв **у телевизора**, кабель перекладывать не нужно.

| Устройство | Цена (ориентир) | Что решает |
|---|---|---|
| CEC-блокер (адаптер без пина 13) | 300–700 ₽ | Гасит CEC-опрос в дежурке |
| EDID-эмулятор / стабилизатор HDMI | 1000–2500 ₽ | Карта всегда видит «живой» дисплей, Windows не пересобирает раскладку |
| Powered HDMI-репитер | ~1500 ₽ | Поднимает уровень +5 В, чистит сигнал на длинной линии |
| HDMI-сплиттер с EDID | 2000–4000 ₽ | Аппаратный клон LG↔ТВ с нулевой задержкой; заодно стабилизирует HPD |

Сплиттер — единственный вариант, дающий «честный» клон без задержки и без окна; он же
снимает проблему мигания.

## 6. Открытые вопросы

- Точная причина периодических импульсов HPD у конкретной модели Philips (CEC-опрос?
  сетевой standby? обновление прошивки?) — не измерялась на уровне электрики.
- Влияние 15-метрового оптического кабеля на качество DDC-линии не проверено заменой
  кабеля (невозможна), поэтому вывод «кабель — усилитель проблемы» остаётся гипотезой.
- Поведение при включённом HDR на телевизоре не тестировалось отдельно.
